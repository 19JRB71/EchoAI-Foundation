SECTION A — THE RISK AND GOVERNING INVARIANT
A1. I-32 as recorded

I-32 was recorded on 2026-08-02.

The Autopilot approve path wrapped the Facebook launch inside its claim transaction. This created a narrow failure window:

provider succeeds → local transaction/commit subsequently fails → retry occurs → second Facebook launch may occur.

The known consequence was bounded:

duplicate launch remains PAUSED/$0 under 015;
no public content is created;
since 018, source-uniqueness can detect the collision and route it to MANUAL_REVIEW.

Those protections reduce damage and provide detection, but they do not constitute exactly-once execution.

D-27 reserved the actual repair.

A2. EXACTLY-ONCE IS PROVIDER-OBJECT LEVEL

A Facebook launch is not one atomic provider action.

It creates four provider objects:

campaign → ad set → creative → ad

Therefore, the governing invariant for Prompt 033 is:

For one approved launch intent, no provider object that was successfully created may be created a second time because local persistence, transaction commit, task transition, process execution, worker execution, or bookkeeping subsequently failed.

The bound applies independently:

campaign create ≤ 1 per approved launch intent
ad-set create ≤ 1
creative create ≤ 1
ad create ≤ 1

A retry may finish a genuinely missing later object.

A retry must never recreate an earlier provider object that already succeeded.
