# REPLIT_PROMPT_004 (v3) — Per-brand Facebook Page and destination link

**Phase B**
**Prerequisites:** Prompt 002 COMPLETE and Prompt 003 COMPLETE.

## Objective

Every Facebook ad launch must resolve its Page ID and destination URL from the correct brand.

No launch path may read:

- FACEBOOK_PAGE_ID
- FACEBOOK_LINK_URL

from global environment configuration.

This applies to:

1. Manual campaign launch
2. Autopilot launch
3. Ad Creative Studio launch

## Reason

Audit finding P1-2 identified global Facebook Page and destination-link configuration as a multi-tenant blocker.

A global Page or link can cause one customer’s campaign to use another customer’s assets or destination.

## Scope

In scope:

- Brand-level ad destination field
- Existing brand-level Facebook Page reference
- Wizard persistence of the selected Facebook Page
- Brand settings UI for the ad destination URL
- Manual launch path
- Autopilot launch path
- Ad Creative Studio launch path
- echoCompanion gating
- setupAgent gating
- Tests, migration, deployment verification and documentation

Out of scope:

- Targeting changes
- Budget changes
- Creative-content changes
- Facebook launcher unification or large refactors
- Production launch
- Activating or spending on ads

`GLOBAL_PROMPT_RULES.md` applies in full.

## 3. Database migration

Add:

`brands.ad_link_url`

Requirements:

- Additive and nullable initially
- Backfill from `brands.website_url` where a valid website URL exists
- Do not overwrite an existing `ad_link_url`
- Verify the migration number is unused in the live repository tree
- Include a safe rollback statement

- Rows backfilled

## 4. Brand-level Page and link resolution

For all three launch entry points:

1. Manual campaign launch
2. Autopilot
3. Ad Creative Studio

Resolve from the authenticated campaign’s correct brand:

- Facebook Page reference
- `brands.ad_link_url`

Never resolve them globally.

Never accept another tenant’s Page or link.

Preserve all existing Facebook connection and Page-ownership validation from Prompt 002.

Manual and Autopilot should continue using the shared launcher.

Ad Creative Studio may retain its current separate campaign/ad-set/creative assembly path during this prompt, but it must use the same correct brand-level Page and link values.

Do not perform the I-22 launcher-unification refactor in Prompt 004.

## 5. Fail-fast behavior

If the brand is missing either:

- A valid selected Facebook Page
- A valid `ad_link_url`

the request must:

- Fail before any Facebook Graph object is created
- Return the existing honest `503` pattern
- Identify the missing configuration
- Give the owner clear instructions for fixing it
- Avoid reporting success
- Avoid creating a partial Facebook chain
- Avoid copying configuration from another brand
- Avoid falling back to global environment variables

Add tests proving zero Graph creation calls occur in this condition.

## 8. Required tests

### Two-brand tenant-isolation test

Using mocked Facebook Graph calls:

- Brand A has Page A and Link A.
- Brand B has Page B and Link B.
- Launch Brand A.
- Launch Brand B.
- Capture the supplied Graph parameters.
- Assert A uses only Page A and Link A.
- Assert B uses only Page B and Link B.
- Assert no cross-brand leakage.

Cover:

- Manual/shared launcher
- Autopilot’s use of the shared launcher
- Ad Creative Studio

### Gating-isolation test

- Brand A is configured.
- Brand B is missing Page and/or link.
- Brand A passes.
- Brand B receives honest guidance.
- No Graph creation call occurs for Brand B.
- Brand B never receives Brand A’s values.

### Environment-removal test

Set misleading test values for:

- FACEBOOK_PAGE_ID
- FACEBOOK_LINK_URL

Prove launch logic ignores them and uses brand data exclusively.
